# User guide

## First use

Use an approved managed browser profile and the approved internal site address. Data belongs to that browser profile and origin, not your login. Do not assume another practitioner can see your events. In Configuration, enter approved role / authority references, enterprise BC Manual reference and information handling text. In Readiness, record evidence and dates for the actual checks. Confirming a local checkbox is not governance approval.

Import the Business Centre template or add records individually. Leave unavailable numbers blank; do not turn unknown exposure into zero. Mark training records DEMO and keep exercises separate from operational records. The default register is empty.

## Guided assessment

Choose New assessment. Record source advice, geography and timing. Select relevant exposure and Business Centres; enter total people only if you can avoid double counting selected centres and other workforce. Review all impact categories. Unknown values remain unresolved; they are not assessed as no impact.

The decision test summarises advice, exposure, timing and impacts. Enter proportionate action and evidenced hazard prompts. Answer the Critical Operations question considering the operation, dependency and impact tolerance; uncertainty requires a hand-off. Select other enterprise needs where appropriate.

The final step records available authority, any BC Director approval for a broader protective attendance direction, recovery phase where relevant, human posture, decision-maker, rationale and review time. An override needs rationale. The recommendation remains separate. Save draft during longer assessments; a successful save is explicitly announced. Complete assessment moves to Live Event mode.

## Live Event mode

The nine-part decision card shows current authority, action, enterprise hand-off, communication and review information. Add recommended actions without retyping; specify an owner and due time if known. Update status to OPEN, IN PROGRESS, COMPLETE or CANCELLED.

Generate workforce, People Leader, senior leadership or event-summary drafts. Edit final text and copy / export it. Send through the approved channel yourself, then mark issued with audience, channel and issuer. The recorded timestamp is when you mark it issued; describe different actual timing in the final text or a follow-up record if needed.

Record the actual enterprise pathway used, recorder, status and evidence. An ACKNOWLEDGED or RESOLVED log entry does not cancel a new assessment's Critical Operations hand-off trigger. Review the latest assessment and advice each time.

## Reassess and compare

Reassess copies the latest inputs into an editable draft. Update stale facts, triggers and review time deliberately. Completing appends a version and freezes its centre data. History & records compares against the preceding assessment, including operational status snapshots. Qualitative changes without a supported ordering are CHANGED, not inferred as worse or better. Impact categories support WORSENED, IMPROVED and RESOLVED; unknown is never ranked as safe. Choose an older version to view its original recommendation and human decision.

## Recovery

Select RECOVER after the immediate threat has passed. Check people, centre availability / enterprise advice, practical access, transport, utilities, backlog, current enterprise advice, communication and lessons. Record evidence. Use NORMAL only after checks are clear; active unsafe or impact flags must be revisited. Close event requires recovery assessment, resolved checks, decision-maker and rationale. Reopen event preserves history.

## Records and failures

Use History & records for a complete independent record, browser print / save as PDF, JSON or assessment CSV. Export all data in Configuration for recoverable backups. Individual decision-record exports are evidence, not restore backups. Export unsaved draft creates a full backup containing the current form.

If save fails, stay on the page. Export unsaved draft, retain the existing browser profile and resolve the cause. A stale-tab error means another tab saved first; export then reload to avoid overwriting it. Do not clear site data as troubleshooting. Deliberate deletion requires typing the event / centre ID; event deletion downloads a safety backup first, but you must verify it was retained.
